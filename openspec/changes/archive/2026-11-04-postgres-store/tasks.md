## 4. Store methods by area (parallel: one agent per area)

**Pattern** (the worked example: `src/store/pg/wards.ts`, `staff.ts`, `seed.ts`, assembled in `store.ts`):

- One module `src/store/pg/<area>.ts` exporting `<area>Area(ctx: Ctx)`, an object of `Store` methods typed with `satisfies Partial<Store>`. `pg/store.ts` spreads it in place of that area's `todo(...)` stubs. Helpers shared by areas go in `pg/context.ts`; a helper calling itself through the area object breaks inference, so keep such helpers as plain functions taking `Ctx` (see `teamOf` in `staff.ts`).
- Queries with Drizzle's builder on `ctx.db`, raw `sql` only where the builder cannot say it (design §4.2a). Times: `at(ms)` in, `iso(d)` out; `count(*)::int`; raw time expressions `.mapWith(<a timestamptz column>)`. Dialect fixes of design §4.3.
- Writes that read first run in `ctx.db.transaction(async (t) => …)` and lock first: the bed (`admission` row) or ward row with `.for('no key update')`, ward before beds (design §4.1). Inner helpers take `{ db: t, now }`.
- Parity first: a `src/store/pg/<area>.test.ts` (copy `pair()` from `store.test.ts`) that runs the area's SQLite store tests' calls on both stores and deep-equals the results; see it fail on the stub, then port. No assertion of an existing test changes.
- Never call a raw `h.pg.query` inside a transaction (PGlite has one connection: it deadlocks). Lock checks use `createTestDb(onQuery)`.
- Do not switch callers here (group 5 does, through `asyncStore`), and do not touch another area's stubs.
